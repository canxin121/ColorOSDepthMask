# ColorOSDepthMask v0.1.11

修复 ColorOS 17 / Wallpapers **17.04.0033** 编辑页不出现“蒙版”入口的问题，并加强启动和界面诊断。

## 本次修复

- **适配 17.x 新工具栏布局。** 系统为图标增加了外层容器，旧版按直接父容器判断，导致放弃创建入口。
  新版同时兼容旧布局和新布局，保留图标、标题、间距与对齐方式。
- **恢复延迟绑定。** 页面或壁纸数据尚未就绪时保留当前 ViewModel，随页面挂载、布局和原生壁纸事件恢复入口；
  布局等待使用事件回调，避免连续空转。
- **修正保存状态读取。** 跟随 17.x 的 COE 状态接口，同时兼容早期和后续 16.x 的差异；
  无法确认处理状态时保留原生按钮行为。
- **完善诊断。** 错过首次启动观察点后仍可通过编辑页生成报告，分别显示 Hook 安装和入口绑定状态，
  记录入口失败原因及报告读取错误。APK 指纹读取失败不会掩盖其他诊断结果。

## 验证与边界

直接使用已发布的 v0.1.10 APK 和 17.04.0033 的真实二进制布局复现了旧版拒绝创建入口；
同一布局下，新版发布包的布局实现通过图标、标题、间距、点击及原生节点保护检查。
完整验证范围及逐项结果见 [v0.1.11 兼容性验证](https://github.com/canxin121/ColorOSDepthMask/blob/main/docs/compatibility-v0.1.11.md)。

这次反馈来自外部测试者的一加 15 国行 PLK110。当前没有该手机的 LSPosed 日志，
因此报告缺失的真机原因尚不能确定，也尚未完成该设备的新版 UI/GPU 验收。
自动测试使用真实 APK 和隔离 Android 进程；厂商控件绘制和真实 LSPosed 引擎仍需对应设备复测。

## 更新

覆盖安装本版本后，在 LSPosed 中确认模块启用、作用域包含 `com.oplus.wallpapers`，
重启 Wallpapers，再打开原来的锁屏编辑页检查“蒙版”入口。
随后检查导入/编辑、保存，以及退出后重新进入。若仍异常，打开模块诊断页刷新并复制诊断信息。
